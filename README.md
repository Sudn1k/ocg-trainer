# Онлайн-тренажёр по ОЦГ

378 вопросов из 7 разделов и три режима подготовки. Тренажёр можно публиковать как статический сайт на GitHub Pages или запускать с Node.js-сервером. Импорт разделов через администратора доступен только на сервере.

## Публикация на GitHub Pages

GitHub Pages публикует автономную сборку с текущей базой вопросов. Пароль администратора и сервер для этой версии не нужны; добавление разделов выполняется обновлением базы и повторной публикацией.

1. Создайте GitHub-репозиторий и отправьте в него файлы проекта. Не добавляйте `.env` и `data/` — они исключены через `.gitignore`.
2. В репозитории откройте **Settings → Pages** и выберите источник **GitHub Actions**.
3. Отправьте изменения в ветку `main`. Workflow автоматически соберёт и опубликует сайт. Ссылка появится в **Settings → Pages** и в результате workflow.

Чтобы опубликовать новые вопросы, положите HTML-файлы в `source-html/` и выполните:

```bash
npm run import -- source-html
npm test
```

Проверьте сгенерированные `src/data/questions.json`, `src/data/questions.js` и `assets/images/`, затем отправьте эти изменения в `main`. GitHub Actions пересоберёт сайт. Если нужно только повторно собрать сайт без изменения базы, выполните `npm run build:pages`; в `dist/` появятся `index.html` и автономная копия `ocg-trainer.html`.

Все вопросы на опубликованном сайте доступны посетителям. Не помещайте в репозиторий секреты, личные данные или материалы, на публикацию которых у вас нет прав.

## Запуск локально

1. Установите Node.js 20 или новее.
2. Запустите `npm start`.
3. Откройте `http://localhost:4173`.

## Минимальное развёртывание на VPS с Caddy

Пример для Ubuntu/Debian. Нужны уже работающий Caddy, Node.js 20+ и отдельный домен DuckDNS, например `ocg-example.duckdns.org`.

### 1. Настройте DuckDNS

На [duckdns.org](https://www.duckdns.org/) создайте поддомен и укажите IP вашего VPS. Не меняйте домен существующего сайта. Убедитесь, что порты 80 и 443 уже открыты для работающего Caddy.

### 2. Загрузите проект

Когда проект будет опубликован в GitHub, клонируйте его на VPS (подставьте адрес своего репозитория):

```bash
sudo mkdir -p /opt/ocg
sudo chown "$USER":"$USER" /opt/ocg
git clone https://github.com/ВАШ_АККАУНТ/ocg-trainer.git /opt/ocg
```

### 3. Задайте пароль и запустите приложение

Создайте настройки:

```bash
nano /opt/ocg/.env
```

Впишите свой пароль администратора:

```dotenv
HOST=127.0.0.1
PORT=4173
ADMIN_PASSWORD=ВАШ_НАДЁЖНЫЙ_ПАРОЛЬ
```

Секрет сессии сервер создаст автоматически. Установите права на файл:

```bash
chmod 600 /opt/ocg/.env
```

Создайте службу systemd одной командой:

```bash
sudo tee /etc/systemd/system/ocg-trainer.service >/dev/null <<EOF
[Unit]
Description=OCG Trainer
After=network.target

[Service]
User=$USER
WorkingDirectory=/opt/ocg
EnvironmentFile=/opt/ocg/.env
ExecStart=/usr/bin/node /opt/ocg/server.mjs
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF
```

Если Node.js находится не в `/usr/bin/node`, замените путь в `ExecStart` на результат команды `command -v node`. Запустите приложение:

```bash
sudo systemctl enable --now ocg-trainer
```

### 4. Подключите домен в Caddy

Добавьте этот блок в конец `/etc/caddy/Caddyfile`. Замените домен на свой; существующую конфигурацию сайта не удаляйте:

```caddyfile
ocg-trainer.duckdns.org {
    reverse_proxy 127.0.0.1:4173
}
```

Проверьте конфигурацию и примените её:

```bash
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
```

Откройте `https://ocg-example.duckdns.org`. Caddy сам настроит HTTPS. Порт `4173` в интернет открывать не нужно.

Если сайт не открылся, проверьте службу:

```bash
sudo systemctl status ocg-trainer --no-pager
```

## Работа с тренажёром

- **Вопросы и ответы** — просмотр вопросов по темам с отмеченными правильными ответами.
- **Случайный тренажёр** — случайные вопросы с настройкой количества и проверкой ответов.
- **По темам** — тестирование по выбранному разделу.

Поддерживаются одиночный и множественный выбор, сопоставление, текстовый ответ и последовательность.

Чтобы добавить раздел на серверной версии, нажмите **«+ Добавить раздел»**, введите `ADMIN_PASSWORD` и загрузите HTML-файл страницы «Просмотр вопросов». Раздел сохранится на сервере и станет доступен другим устройствам. На GitHub Pages кнопки добавления разделов нет: обновляйте базу вопросов и публикуйте её новой сборкой.

Для добавления вопросов из исходников поместите HTML в `source-html/`, затем выполните:

```bash
npm run import
npm test
```
